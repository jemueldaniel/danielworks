## Repeatably demonstrate skills at an interview

Check out the exact verified public commit and compare its
SOURCE_MANIFEST.json SHA-256 with an **externally recorded pin**.

Run the fixed one-shot profile ui-atlas into a fresh empty directory.
Open it using a localhost static server and show five different
functioning interface types. Search a synthetic catalog, add items,
change quantities, inspect the simulated checkout; create and move a
Kanban task; send a literal local message; complete the onboarding
steps; and download the original JSON tokens. In each view, test
320-pixel mobile and 1280-pixel desktop layouts and inspect keyboard
focus. Then run the pinned Node and full installed-Edge browser tests.

Review program structure: pure data model, deterministic reducer,
DOM text-node rendering, bounded inputs, semantic HTML and CSS tokens.
Explain the negative tests and where real production integrations would
introduce new security and data-protection obligations.

## Evidence and confidentiality limits

- Public original examples prove tested generic implementation, not sole
  authorship, redistribution rights or complete production status
  for any separately private product.
- No private startup UI, unreleased company names, personal user data,
  private asset libraries, secrets or credentials are inputs.
- Synthetic carts and plans do not process payments or establish pricing
  for any real product. Synthetic chat does not connect to a real user.
- The automated scan for configured sensitive patterns cannot prove that
  every possible confidential material or third-party license is absent.
- True production qualification requires reviews of design goals, a11y,
  UX research, consent, data lifecycle, performance, security and hosting.
